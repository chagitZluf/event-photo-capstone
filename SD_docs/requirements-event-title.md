# \# מפרט דרישות: שינוי כותרת אירוע

# 

# \## 01 | מקור ועובדות

# \- עובדה: השדה `title` מוגדר בקובץ `types.ts` כשדה חובה מסוג טקסט באובייקט האירוע.

# \- עובדה: האירועים שמורים בקובץ `memory-store.ts` — זה המקום שממנו הגלריה שולפת את הנתונים.

# \- עובדה: בקובץ `event-service.ts` קיימות נקודות קצה מסוג GET ו-POST בלבד — אין נקודת קצה מסוג PUT לעדכון כותרת.

# 

# \## 02 | שחקנים והיקף

# \- שחקן: בעל האירוע (הלקוחה שיצרה את האירוע)

# \- היקף: עדכון הכותרת המוצגת בגלריה של הלקוחה

# 

# \## 03 | דרישות פונקציונליות

# \- דרישה 1: המערכת תאפשר עדכון כותרת של אירוע קיים לפי מזהה האירוע

# \- דרישה 2: הכותרת המעודכנת תוצג מיד בגלריה של הלקוחה

# 

# \## 04 | דרישות לא פונקציונליות

# \- דרישה 1: פעולת העדכון תחזיר תשובה תוך 2 שניות

# \- דרישה 2: רק בעל האירוע יוכל לשנות את הכותרת

# 

# \## 05 | הנחות

# \- הנחה: יש להוסיף נקודת קצה מסוג PUT — כרגע היא לא קיימת בקוד

# \- הנחה: קיים מנגנון זיהוי משתמש במערכת

# 

# \## 06 | שאלות פתוחות

# \- שאלה: מי רשאי לשנות את שם האירוע — רק הבעלים, או גם מנהל?

# \- שאלה: האם יש כללי תיקוף לכותרת (אורך מינימלי/מקסימלי)?

# \- שאלה: האם צריך לשמור היסטוריה של שינויי כותרת?

# 

# \## 07 | קריטריוני קבלה

# \- בהינתן אירוע קיים עם כותרת שגויה ולקוחה מחוברת עם הרשאות

# &#x20; כאשר הלקוחה שולחת כותרת חדשה ותקינה

# &#x20; אז הגלריה מציגה את הכותרת החדשה

# 

# \- בהינתן כותרת לא תקינה (ריקה או ארוכה מדי)

# &#x20; כאשר הלקוחה שולחת את העדכון

# &#x20; אז המערכת מחזירה שגיאה והכותרת לא משתנה

# 

# \## 08 | עמימויות

# \- לא ברור אם הכותרת חייבת להיות ייחודית בין אירועים

# \- לא ברור אם הגלריה מתעדכנת בזמן אמת או דורשת רענון דף

# 

# \## 09 | מידע חסר

# \- לא נמצאה נקודת קצה מסוג PUT בקוד הקיים

# \- כללי ההרשאות לא מתועדים

# 

# \## 10 | היקף

# \- בתוך הסקופ: עדכון כותרת אירוע דרך ה-API

# \- מחוץ לסקופ: עיצוב מסך, שינוי שדות אחרים, מחיקת אירועים
